## 一、为什么做这个 App

### 1.1 起因

市面上的待办 App 有一个共同问题：**它们为"重度效率用户"设计，却让普通家庭成员用不下去。**

- 功能越来越多：项目、标签、看板、协作、订阅、AI……
- 学习成本高：新用户（尤其不爱折腾软件的人）打开后不知道从哪下手。
- 数据不在自己手里：账号、云同步、隐私条款，还可能哪天停服数据就没了。
- 价格：好用的大多要订阅。

而我们真正需要的，其实非常小：

> **想到一件事 → 记下来 → 到点被提醒 → 做完了勾掉。**

### 1.2 我们要解决的问题

| 痛点 | 我们的做法 |
|---|---|
| 打字麻烦，尤其手机上 | **语音输入**，说一句就记下 |
| 功能太多不敢点 | **只有清单 + 完成 + 时间**，没有多余概念 |
| 不确定数据在哪、会不会丢 | **全部在本机**，可导出可备份可迁移 |
| 到期忘记 | **本地提醒**，准点通知，不依赖自己的服务器 |
| 想给别人看/存档 | **可导出 PDF / Markdown** |

### 1.3 核心信念

| 原则 | 说明 |
|---|---|
| **数据不出本机** | App 自身不把任何数据上传到任何服务器；所有功能在本机完成 |
| **数据是自己的** | 一个 SQLite 文件 + 可导出 JSON，随时带走 |
| **能少则少** | 每加一个概念（项目/标签/优先级）都要先说服自己 |
| **能点/能说就别打字** | 时间选择用大按钮，标题优先语音 |
| **出错可撤回** | 误删、误完成一律可撤销 |
| **降级不阻塞** | 语音失败、精确闹钟被拒、备份目录失效——都退化为可用状态，绝不静默失效 |

> **关于联网的准确口径**：App 自身的业务数据完全本地、绝不联网。但**语音识别调用系统能力，Android 上底层通常是 Google 语音服务，会联网**。所以：
> - 我们**不宣称"App 不申请联网权限"**（那不成立）；
> - 我们说"**你的任务数据不会离开这台设备**"；
> - 该口径写死在"关于"页文案里（见 02 §5.1）。

## 二、产品定位

### 2.1 一句话定义

> **"朝夕" —— 一个装在自己手机和电脑里的极简待办清单，说句话就能记，到点会提醒，数据全在本地。**

### 2.2 它不是

- ❌ 不是团队协作工具（没有共享、没有指派）
- ❌ 不是项目管理工具（没有项目/看板/甘特）
- ❌ 不是笔记软件（备注只是辅助，不做富文本）
- ❌ 不是"效率方法论"载体（没有 GTD、没有四象限、没有番茄钟）
- ❌ 不是一个要上架赚钱的产品

### 2.3 它是什么

一个**家庭成员各自使用的私人清单**：
- 作者一份，家人一份，彼此独立、互不干扰；
- 未来若需要，才考虑"把两份合起来看"（本版本不做）。

## 三、目标用户

### 3.1 用户画像

| 维度 | 作者 | 家人 |
|---|---|---|
| 设备 | Mac 为主 + Android | Android 为主 + 偶尔 Mac |
| 技术水平 | 会写代码，但也想要"别麻烦我"的工具 | **懂用电脑手机，但不懂软件开发** |
| 使用频率 | 每天多次，随手记 | 每天几次，想到就记 |
| 主要诉求 | 快、不打断思路、数据可备份 | 简单、字大好看、别让我学 |

> **关键约束**：家人是判断"这 App 好不好用"的标准。**任何需要看说明书才能用的设计都算失败。**

### 3.2 使用场景

**场景 A｜做饭时想到要买盐**
> 手上是油。掏出手机 → 点麦克风说"买盐" → 松手，任务直接进清单。不弹层、不跳页。

**场景 B｜明天要交材料**
> 新建任务"交材料" → 点"明天" → 时间落在明天 09:00 并自动提醒（只选日期时默认上午九点，可改）→ 到点提醒。

**场景 C｜月底写月报**
> 月末，她把范围选成"本月"、清单选成"工作"，一键导出 Markdown → 按周分好的完成清单，直接拄进月报。

**场景 D｜换手机 / 怕丢**
> 设置里点"导出备份" → 得到 JSON 文件 → 存到网盘/发给自己。新手机上"导入恢复"。

**场景 E｜重复的家务**
> "每周三倒垃圾"设成每周重复。勾掉后，**同一条任务推进到下周三**（不是复制出新的一条），到期继续提醒。代价：它不会在"已完成"里留下每一天的记录，但任务行上会累计"已做过 N 次"。

## 四、范围

### 4.1 范围内（要做）

- Android App + macOS App，一套代码
- 任务的增 / 删 / 改 / 查
- 截止时间 + 本地提醒
- 重复任务（P1）
- **语音输入标题**（首页可直接说，编辑页也可说）
- 视图：**待定 / 今天 / 明天 / 本周 / 本月 / 以后 / 全部 / 已完成**（可显示隐藏/排序/重命名，见 02 §2.2.1）
- **工作 / 生活 清单**（与时间视图正交）
- 拖拽排序
- 导出 PDF / Markdown / JSON，导入恢复
- **按范围（本月/本周/自定义）导出报告，含未完成章节**
- 自动备份（P1）
- 深色模式（P1）

> **MVP 边界（本文档口径）**：MVP = **全部 P0 需求**，对应里程碑 **M0 + M1（提醒部分）+ M2 + M3**。
> 此外先交付一个 **v0.1 可日用版本 = M0 + M1**（CRUD + 提醒，无语音、无导出），用两周再决定后续节奏。
> （评审建议把 M2/M3 移出 MVP；本版**保留语音与导出为 P0**，因为这是明确的原始需求。若你认同评审，把 02 §六 对应项降到 P1 即可，其余文档无需改动。）

### 4.2 范围外（明确不做）

| 不做 | 原因 |
|---|---|
| 云同步、多设备 | 本期明确推迟；架构预留即可（见 04 §十） |
| 账号注册 / 登录 | 纯本地不需要 |
| 多人共享清单 | 各自独立使用 |
| AI 拆解、智能建议 | 明确推迟 |
| 项目 / 标签 / 看板 | 复杂度收益比低 |
| **子任务 / 拆解**（US-030） | P2/M5，本期不做 |
| 富文本备注 / 附件 / 图片 | 需要时再评估 |
| 上架应用商店 | 侧载 APK + 本地 .app 即可 |
| 订阅 / 付费 | 自用 |

## 五、为什么不直接用现成的

| 现成方案 | 为什么不用 |
|---|---|
| Apple 提醒事项 / Google Keep | 各自平台割裂；Android + Mac 组合体验差 |
| Microsoft To Do / TickTick | 功能多、要账号、数据在云端 |
| Things / OmniFocus | 只覆盖 Apple 生态，且复杂、付费 |
| Obsidian Tasks / 纯文本 | 需要维护文件、无提醒、家人用不了 |
| 纸质便签 | 不会提醒、不能搜索 |

**一句话**：现成方案要么不够简单，要么数据不在自己手里，要么 Android + Mac 不同时支持。

不看下载量，只看这几条：

| 指标 | 目标 |
|---|---|

## 七、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 语音识别不准（口音/环境） | 用户放弃语音 | 语音只是**加速器**，随时可手改；不把它当唯一入口 |
| 语音依赖系统联网，无网时不可用 | 体验断裂 | 手动输入路径永远可用；无网时给明确中文提示 |
| 纯本地，手机丢了/坏了数据没了 | 数据丢失 | 强制可导出 + 自动备份到用户指定目录 |
| Android 精确闹钟被拒 → 提醒不准 | 核心卖点失效 | 声明并由用户授权；被拒则降级为不精确并**显式提示**，绝不静默 |
| mac 沙盒下备份目录重启后失效 | 备份静默失败 | 持久化 security-scoped bookmark（见 04 §5.2） |
| Mac / Android 体验割裂 | 用着别扭 | 共用一套 UI 规范，桌面端做键盘快捷键适配 |
| 功能越加越多 | 违背初衷 | 任何新功能先进"范围外"表，两周后还想加再说 |
| Flutter 桌面端打包/签名麻烦 | 卡住 | 先跑 debug/本地 `.app`，签名最后处理；M0 期间先跑通一次 macOS 构建 |
