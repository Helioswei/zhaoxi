以下为当时的分析过程，留作回溯：


**问题**：实测下来，「以后 / 待定 / 全部」显得重复。分析后确认：

- 「全部」在内容上 **= 其他所有视图的并集**（真正重复的那个）；

**行业惯例**（调研，见下表）：主流 App 都只有 3–5 个时间视图，且**几乎没人把"明天/本周/本月"做成平级标签**——它们是"即将到来"这条连续时间线里的**分组标题**。

### D-6 动画体系（建议待拍板，2026-10-22 调研）

**调研结论**：项目目前没有自有动画体系，全靠 Flutter 默认（弹层上滑、snackbar、水波纹、拖拽跟随、唯一的 Dismissible）；用户最有感的时刻全是瞬变：勾完成、任务行出现/消失、弹层内展开备注/时间、切风格、深浅色切换。

**建议方案（克制路线，每处 ≤300ms，不弹跳不花哨，保持"松弛贴手"）**

核心三件（P1）：
1. **完成动画**：划线渐显 150ms（AnimatedDefaultTextStyle）+ 完成钮弹一下——"做完小事"的满足感，对家人最有价值的一处
2. **任务出现淡入+微上移** ~200ms：新建/undo 恢复的落定感（AnimatedList 或 itemBuilder 包 FadeTransition）
3. **弹层内展开/收起**：时间/重复/备注 AnimatedSize ~200ms

顺带（P2）：
4. 切风格/深浅色全程渐变（新版 Flutter theme 切换动画 API，成本低）
5. 筛选 pill 选中 150ms 过渡

量级：P1 约半天，P1+P2 约一天。待用户拍板范围后实施。

### D-7 自研文件列表（方案 C）✅ 已实现（2026-10-22）

背景：小米等 ROM 的系统选择器不显示文件名（见 T-9），所以做了"借一次目录授权、列表自己画"的方案。

**做法（C 档）**
- 首次进「从文件恢复」→ 引导页 → 点「选择文件夹」→ 系统目录界面选一个目录 → 点「使用此文件夹」→ 允许。
  这一步**只需要点，不用认文件名**（文件名空白也无所谓），之后再也不出现。
- 之后列表全在 App 内：文件名、大小、修改时间、子目录来源、搜索（>5 个才出搜索框）、刷新、换文件夹。
- 递归 3 层、最多 300 个，只收 `.json` / `.txt`；按修改时间倒序（刚传进来的在最上面）。
- 授权 `takePersistableUriPermission` 持久化，重启仍有效；换文件夹时释放旧授权。
- 兜底：引导页底部保留「或者用系统文件选择器试一次」。

**写入（2026-10-23）**
- 「存到文件夹」也走同一套目录授权：`createDocument` 直接写进这个文件夹，**不弹系统「新建文件」对话框**。
- 备份页按钮会变成「存到『<文件夹名>』」；没授权过就先跳去选一次，选完自动接着存。
- 存进去的 JSON 立刻出现在「从文件恢复」列表顶部，存 / 取闭环。
- 只读来源（网盘）会失败，映射成 `no_write` 并提示换一个文件夹。

**已知限制（系统层面，绕不开）**
- Android 11+ 不允许把**内部存储根目录**或 **Download 根目录**授权给 App（会显示「Can't use this folder」），
  必须选其中的子文件夹。引导文案已提示，实际用法：`Download/朝夕备份` 之类的专用文件夹。
- 部分 ROM 的系统「新建文件夹」对话框里**输入框看不到已输入的文字**（系统 UI 的问题，App 改不了）；
  引导已改为「用手机自带的『文件管理』先建好，再回来选」。
- 只列授权目录子树内的文件；别处的文件仍需用「分享到朝夕」（T-9）。

实现：`TreeBrowserChannel.kt`（openTree/list/readText/createFile/release）+ `tree_source.dart` +
`restore_files_page.dart`，授权 uri 存在 settings（`restore_tree_uri` / `restore_tree_name`），无新增依赖、无危险权限。

### T-9 说明（系统文件选择器问题）— ✅ 已解决

现象：在部分国产 ROM 上，系统「文件」选择器的**目录名/文件名/侧栏名称全部不显示**（只剩图标），
搜索框里输入的字也看不见，深色模式同样空白 —— 其他 App 正常（它们走厂商文件管理/MediaStore）。
实测结论：换 Intent 无解。同一文件在小米上，`OPEN_DOCUMENT × 5 种写法` 渲染完全一致；
点名让小米「文件管理」接手也失败（它不接 `OPEN_DOCUMENT`，系统直接报
`No activity found to handle intent`）。这是 ROM 的选择器渲染 + 注册缺失，App 侧改不动。

已落地方案（T-9）：
- 注册 `ACTION_SEND`（`application/json` / `text/plain` / `application/octet-stream`）
  与 `ACTION_VIEW`（`application/json`，`file` / `content` scheme）；
- 原生读到文件名 + 内容后推给 Flutter，复用「合并 / 覆盖」弹窗，弹窗里显示文件名；
- 冷启动（App 没开）与热启动（已在前台）都覆盖：原生 `onCreate` / `onNewIntent` + 主动推送；
- 不是朝夕备份的文件只提示「这个文件不是朝夕的备份」，不弹恢复窗；
- 读不到（对方没给授权）时提示「读不到 xxx，先把它保存到手机再试」。

用户流程：微信收到 json → 长按 → 用其他应用打开（或分享）→ 朝夕 → 合并或覆盖。
备份页「从文件恢复」下方也加了这条提示文案。依赖：无第三方插件（原生 MethodChannel 自实现）。
